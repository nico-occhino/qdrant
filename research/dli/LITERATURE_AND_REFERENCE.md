* Sommerová, chapter 3 §§3.1–3.3 (printed pp. 31–34; PDF pp. 43–46): buffer capacity b, arity a, level i has a^i buckets, maximum b a^i and minimum b a^(i-1). Bentley–Saxe collects buffer and intervening higher levels into a target with sufficient space; leveling moves data successively. Do not assume partial destination insertion is safe for immutable Qdrant LMI generations.
* Sommerová §§3.3.2–3.4 (printed pp. 34–38; PDF pp. 46–50): multiple retraining policies; hard deletion and underutilization-triggered basic/greedy rebuilding. Qdrant must preserve its own delete and visibility semantics rather than imitate hard deletion.
* Sommerová §3.5 (printed pp. 38–40; PDF pp. 50–52): every nonempty model predicts; global bucket ordering includes the buffer; whole buckets are selected until the candidate minimum is met. Normalized score is P(bucket|query) a^i, with buffer score 1. This scaling addresses differing output counts but does not prove statistical calibration.
* Plhák chapter 2 §§2.3–2.6 (printed pp. 12–18; PDF pp. 24–30): Bentley–Saxe insertion; clustering and router training; normalized global bucket selection; deletion with ID-to-location map and swap/pop, with optional rebuild. See figures before treating visual details as verified. In `index.rs::records2visit`, physical zero-based level index is used in `arity.pow(level_idx)` while `add_level` uses `arity.pow(level_idx + 1)` buckets; buffer score remains 1. This differs by a factor of arity from the thesis's one-based formula relative to the buffer and merits a focused reference test before adoption.
* Jakubík chapter 1 §§1.1–1.3 (printed pp. 5–7; PDF pp. 13–15): the earlier class-incremental DLI expands classifier outputs and splits selected buckets; CLI splits overflowing buckets and studies forgetting. This differs fundamentally from the independently trained temporal hierarchy. No CLI is implemented here.

## Reference implementation

[Plhák Rust reference](https://github.com/simonplhak/DynamicLearnedIndex/tree/4e756476ae9352fcef7896cf5ef551282751c32b), revision `4e756476ae9352fcef7896cf5ef551282751c32b`. Selected source files are in the experiment directory `reference/`; this is not a full clone. `Index` owns levels, buffer and cache; `insert` fills buffer and calls Bentley–Saxe compact; `available_level` accumulates intervening occupancy and chooses a destination with sufficient capacity; `lower_level_data` materializes records/IDs; empty/new targets retrain/train, then `insert_many` predicts assignments. `LevelIndex` owns model and storage. `delete` checks buffer then levels and may rebuild. `records2visit` ranks nonempty buckets globally and scores complete selected buckets. `dump` writes model, data and metadata; inspecting these writes does not establish transactional crash recovery. Cold storage and LRU are reference-specific; Qdrant should retain authoritative storage and native lifecycle. The current inspection does not yet establish all cold-storage error/recovery behavior or cross-thread guarantees.

### 2026-11-12 numerical normalization control

For arity 3 and a level-1 bucket probability 0.4, Sommerová §3.5.1 (printed p. 40; PDF p. 52) gives 0.4 × 3 = 1.2 while Plhák's zero-based `records2visit` at the pinned revision gives 0.4 × 3^0 = 0.4. Both give the buffer priority 1.0. Thus this bucket ranks above the buffer in the former and below it in the latter. Learned-level scores differ by the common factor 3, leaving their mutual ordering unchanged; buffer-relative ranking is genuinely different. The deterministic mock control is in `prototypes/budget_control.rs`; this comparison does not infer author intent or claim a calibration guarantee.

Reference cold storage uses per-bucket disk extents in 64 KiB blocks and an in-memory ID set (`cold_storage.rs`). This is a distinct vector storage implementation and is not being imported.
