# Generation and publication contract — experimental

External point IDs identify logical points. Offsets belong only to a physical segment's offset space. Physical UUIDs identify native segment generations; holder IDs are transient runtime locators. Logical level ID and level generation identify temporal organization. The experiment binds model/posting state through the pinned native Segment object, whose loaded LMI validates router/posting structure; it does not independently version models. View generation identifies a particular membership publication, not a point-in-time data snapshot.

The test-only controller owns a registry mutex and a native LockedSegmentHolder. Capture takes registry mutex then holder read lock, validates physical UUID, dimension, metric and learned state, then clones the original native Arc handles. Controlled replacement takes the same mutex and holder write lock, swaps membership and advances the descriptor/view generation. A bypassing native replacement causes later capture to fail on missing or mismatched physical identity. Proxy members are rejected. This adapter demonstrates a restricted in-memory boundary; production optimizer paths do not take its mutex and would need a shared publication contract. Capture is fail-closed, not automatically self-healing.

Routes carry view generation, member ordinal and physical UUID. Scoring validates those bindings and reads the pinned object's model/posting/storage association. Internal code generates offsets from the same pinned postings. Arbitrary caller-supplied offsets, forged bucket membership or concurrent index mutation are outside this test adapter's trusted interface. Mutable buffer membership is pinned, but its contents and point versions can change; this is not MVCC. Native update APIs must continue to own mutation semantics and lock ordering.

Alternatives: storing level metadata in the holder could use its existing lock, but needs production lifecycle integration; rebuilding from a durable holder generation requires metadata that does not exist today; an independently published Arc view cannot guarantee consistency with separate holder/manifest updates. The experiment's mutex is a test boundary, not a production decision.

Durability remains unresolved. Integrated metadata publication must join native proxy propagation, final update exclusion, replacement flush/version readiness, holder swap, segment-manifest sync and deferred old-data cleanup. Derived metadata would need durable physical descriptors, a generation selection rule, source coverage validation, stale/orphan handling and a recovery precedence consistent with WAL and pending proxy logs. Neither has been established as safe.

Failure plan: inject failure before private build, during build, before swap, after swap before native manifest sync, after sync before cleanup; test cancellation and propagation failure, upsert/delete arriving in each phase, clean reopen and process interruption separately. Assert one valid membership, latest completed updates, paired model/posting generation and no resurrection. Existing source controls are useful but do not test this registry. No persistent manifest is introduced. Bentley–Saxe compaction remains gated.

The replacement helper has a strict research precondition: no writes occur between private replacement construction and publication. It does not replay deltas or validate a source mutation boundary and therefore must never be used for concurrent update/rebuild publication. The barrier test interleaves a read with replacement only. Native mutation tests are separate. A pending-upsert/replacement test is deferred until a validated proxy/delta adapter exists; using this helper for that scenario could resurrect stale data.

Native optimizer continuation: writes during the paused builder phase now pass through real proxy/COW and native publication/cancellation. The test rebinds the registry after completion solely for oracle verification. It does not make registry capture atomic with proxy installation, native finalization or recovery. See [recovery matrix](DLI_RECOVERY_MATRIX.md) for the superseding M2 gate assessment.

Derived-view candidate: after native LocalShard WAL replay succeeds, validate durable descriptors against the recovered holder under a coherent membership synchronization boundary; if any validation fails, mark degraded and use complete native exact search until reconstruction. Native recovery errors propagate. This is a hypothesis, not an implemented fallback; neither availability during rebuild nor synchronization with future optimizer swaps has been demonstrated.

Full coverage remains mandatory: validation must account for each active searchable segment, including new buffer members and segments without visible fixture IDs. A test-only set built from visible point owners cannot prove this. The `prevent_unoptimized` mode can queue WAL tail operations beyond `load_from_wal` return, so activation must either account for its semantics or restrict the supported mode.
